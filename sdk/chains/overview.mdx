You can connect viem or wagmi to BOT Chain mainnet or testnet by importing one chain object from `@uzolabs/sdk/chains`.

<EarlyRelease />

## The two chain objects

| Export | Network | Chain ID | Native currency | RPC | Explorer |
| --- | --- | --- | --- | --- | --- |
| [`botChain`](/sdk/chains/bot-chain) | Mainnet | 677 | BOT | `https://rpc.botchain.ai` | [scan.botchain.ai](https://scan.botchain.ai) |
| [`botChainTestnet`](/sdk/chains/bot-chain-testnet) | Testnet | 968 | tBOT | `https://rpc.bohr.life` | [scan.bohr.life](https://scan.bohr.life) |

Both are viem `Chain` objects built with `defineChain`. You can use them anywhere viem or wagmi asks for a chain.

## Why use them

A chain object is only a few lines, but they're easy to get wrong. The SDK's objects include two values that hand-written versions often miss:

- **The Multicall3 address.** BOT Chain's Multicall3 is at `0x47FA21f684bBAD707A53a0f9BE59F1422F46C265` on both networks. The standard address that many tools assume has no code on testnet. With the SDK's chain objects, viem's `multicall` and wagmi's `useReadContracts` work without any extra setup.
- **The explorer API URL.** `blockExplorers.default.apiUrl` points at BOTScan's v2 API, which the [explorer client](/sdk/explorer/overview) uses.

## How to use them

```ts clients.ts
import { createPublicClient, http } from "viem";
import { botChain, botChainTestnet } from "@uzolabs/sdk/chains";

// Choose the network once and pass the chain everywhere.
const chain = process.env.NETWORK === "mainnet" ? botChain : botChainTestnet;
const client = createPublicClient({ chain, transport: http() });

console.log(chain.name, await client.getChainId());
```

Choosing the chain in one place means your addresses, explorer links and clients always match. The [contracts module](/sdk/contracts/addresses) uses the same idea: `getAddresses(chain.id)`.

To use your own RPC endpoint, pass it to the transport: `http("https://your-rpc.example")`. The chain object stays the same.
