You can look up any core BOT Chain contract address for mainnet or testnet with `getAddresses(chainId)`, and get it back as a typed value.

<EarlyRelease />

## Import

```ts Import
import { addresses, getAddresses } from "@uzolabs/sdk/contracts";
```

## getAddresses

```ts Signature
function getAddresses<chainId extends 677 | 968>(chainId: chainId): (typeof addresses)[chainId];
```

<ParamField path="chainId" type="677 | 968" required>
  The network. Use `botChain.id` or `botChainTestnet.id` so the chain and addresses always match.
</ParamField>

<ResponseField name="returns" type="object">
  The address map for that network. Each value is a checksummed literal address type, and keys that don't exist on that network aren't in the type.
</ResponseField>

Throws [`UnsupportedChainError`](/sdk/reference/errors#unsupportedchainerror) for any other chain ID. That matters when the ID comes from a wallet at runtime, because TypeScript can't check it there.

```ts addresses-example.ts
import { botChainTestnet } from "@uzolabs/sdk/chains";
import { getAddresses } from "@uzolabs/sdk/contracts";

const { usdt, bridgeRouter } = getAddresses(botChainTestnet.id);
console.log(usdt, bridgeRouter);
```

```text Output
0x75edC9335175Fc0552D51D48439F229c10420fe3 0x6239404Aa276ba68486E2Fa40E90CDd36ff8ec3A
```

## addresses

`addresses` is the same data as a plain object keyed by chain ID: `addresses[677].usdt`. Use it when you need both networks at once, for example to build a table. Use `getAddresses` everywhere else, because it validates the chain ID.

Notes:

- **`universalRouter` is testnet only.** A mainnet Universal Router hasn't been confirmed, so the SDK leaves it out. `getAddresses(677).universalRouter` is a type error.
- **`bridgeRouter` is an upgradeable proxy** on both networks. Its address stays the same when the logic behind it changes. See [ABIs](/sdk/contracts/abis#proxies).
- **USDT has 6 decimals** on BOT Chain. Use `TOKENS.USDT.decimals` from [Constants](/sdk/contracts/constants).

For explorer links to each address, see [Contract addresses](/reference/contract-addresses).
